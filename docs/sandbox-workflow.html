01 / NETWORK & EXECUTION

The app server lives inside the sandbox

Your device sends input and receives the app interface. The controller authorizes project access and routes the connection. Project code and agent processes stay inside the selected sandbox.

Browser target: sign in to the controller, select a project, and open T3. Transparent app pairing through the gateway still needs qualification. Controller login alone does not currently authorize T3 or Orca.

What “local files” means

The app server's local checkout is inside this project's sandbox. Registering /workspace/repo there keeps agent execution and worktree creation in the right place.

What the controller stores

Project metadata, policies and access records. Repository working files, worktrees and app sessions live on the project's own volume. The gateway routes traffic; it does not mount every checkout.

Logical topology. Transport may use a trusted relay rather than a direct worker listener. Ordinary pods and proxies are outside the worker's sandbox boundary. This page does not specify a public ingress or grant new network access.

Original repository: use an existing repository you are authorized to work on. The sandbox gets access only to that repository. GitLab and arbitrary external-source support are planned additions.

What would you set up once?
  • Sign into the controller on each device.
  • Connect the Git accounts or installations the controller may use. Private source imports need authorized read access.
  • Authorize model providers through a supported credential flow. Safe delegation to sandboxes needs separate work; one login for every future sandbox is not yet guaranteed.
  • If using native apps, pair each device with each sandbox's app server once. A stable sandbox identity should preserve that pairing when you reconnect.

IMPLEMENTATION STATUS

What these diagrams commit to, and what remains open

Design requirements

  • One separate sandbox and volume per project.
  • All project execution happens inside its sandbox.
  • Stock app builds are preferred; custom builds require discussion first.
  • Phones connect without a personal desktop relay.
  • Controller credentials and broad account access stay outside workers.
  • Egress rules and repository permissions remain project-specific.

Still to implement or qualify

  • Persistent Orca server packaging and access inside each sandbox.
  • Browser routing, WebSocket behavior, app pairing and revocation.
  • Grok Build and Cursor credential flows; current integration enables Codex only.
  • GitLab repository access and the optional Forgejo import flow.
  • App-specific phone/browser feature coverage and native connection steps.
  • Interrupted provisioning and removal recovery in disposable environments.
